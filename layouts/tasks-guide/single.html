The file, annotated

Sixteen notes, one file. Almost all of version {{ $spec.Params.version }} shows up here. What doesn’t: the file conventions of §4 (UTF-8; LF preferred, CRLF accepted) and how apps map the file to their interface (§13).

Below is the specification’s own quick example (§6). Each line is coloured by its type: the document title, section headings, tasks, metadata, notes, the archive separator and blank lines. The notes around the file state the rules each line depends on. Press a note to light up the lines it governs and read its rules in full below the file.

How to use it. Press a note beside the file to light up the lines it governs and keep only that note here. Press it again, or Escape, to see all sixteen.

Seven line types

A note is defined by what it isn’t: it doesn’t begin with checklist, heading, metadata or separator syntax (T-13).

A reader goes through the file top to bottom (T-36) and gives each line one of seven types (§7). The shape of a line decides its type; its indentation decides where it belongs.

Four states

Only these four tokens are valid in {{ $spec.Params.version }} (§7.4). The specification doesn’t define moves between states.

A task is in one of four states, written as a token between the brackets. Three of them have a recommended companion metadata line that records when it happened (§10).

Reading order

  • - [ ] Ship beta
  • @due: 2026-04-01
  • Waiting on icons.
  • - [ ] Email QA inherits @due

Fig. 3. Each line hangs from the block one level up.

Read top to bottom and keep the line order (T-36, T-37). A metadata line attaches to the nearest preceding non-nested task one level up (T-40). A note attaches to the nearest preceding heading or task one level up (T-41), and a nested task to the nearest preceding task one level up (T-42). Subtasks inherit their ancestor’s effective metadata (T-29), so writers don’t copy it down (T-31).

Everything above the archive separator is active; everything below it is the archive (§5), which stays valid Plaintext Tasks (T-32). Readers keep blank lines when practical (T-38) and preserve unknown metadata keys as written (T-39).
